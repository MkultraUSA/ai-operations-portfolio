# Portfolio Information Architecture

## Positioning

**Portfolio category:** AI Operations and Automation Portfolio

**Core message:** I build practical AI-assisted systems that keep work moving across models, machines, repositories, messaging systems, and interruptions.

**Credibility stance:** practical systems builder and power user. Avoid claiming to be an "AI expert." Show the operating system around AI: persistence, handoffs, observability, workflows, and integration.

## Target Roles

- AI automation specialist
- AI operations analyst
- Technical operations specialist
- Systems integration specialist
- Developer support / internal tools builder
- Applied AI workflow engineer
- Lab operations / technical program support

## Site Map

### 1. Home

Purpose: make the role fit obvious within 10 seconds.

First screen:
- Name and role positioning
- One-sentence operating thesis
- Three proof tiles: Context Forge, Battle Buddy, Infrastructure Lab
- Direct links to case studies, GitHub, LinkedIn, and resume

Primary proof:
- "Context Forge MVP implemented"
- "Codex reads a dedicated Nextcloud filesystem vault"
- "Hermes can read an additive v1 snapshot through `/opt/data/ContextForge`"
- "Evidence-backed handoffs prevent restart-from-zero work"

### 2. Case Study: Context Forge

Purpose: flagship proof of AI operations thinking.

Page sections:
- Problem: AI work fragments across tools, machines, chats, and interruptions
- Solution: portable, scoped, human-readable project memory
- Architecture: Codex, vault, Nextcloud, Hermes, handoff records
- Workflow: investigate, build, test, document, handoff, resume
- Proof: screenshots, sanitized journals, GitHub history, before/after examples
- Outcome: less context loss, cleaner handoffs, safer continuity
- What this shows employers: systems integration, operational discipline, automation design

### 3. Case Study: Battle Buddy

Purpose: show real-world technical operations in a messy operational environment.

Page sections:
- Problem: public-safety radio/transcript data is fragmented and time-sensitive
- System: radio ingestion, transcription, enrichment, database/search, notifications
- Proof assets: transcripts, incident timelines, system diagrams, sanitized logs, screenshots
- Outcome: searchable event memory and faster situational review
- What this shows employers: Linux/VPS work, pipelines, APIs, data handling, reliability habits

### 4. Case Study: Infrastructure and Home Automation Lab

Purpose: show hands-on systems operations beyond one project.

Page sections:
- Problem: maintain a practical technical lab spanning local devices, cloud services, dashboards, and automations
- System: Home Assistant, InfluxDB, Grafana, Nextcloud, Tailscale, SSH-accessible hosts, scheduled jobs
- Proof assets: dashboards, topology diagrams, sanitized runbooks, uptime/restart notes, before/after monitoring
- Outcome: observable local infrastructure and repeatable operational workflows
- What this shows employers: troubleshooting, integration, monitoring, documentation, ownership

### 5. Proof Library

Purpose: make the portfolio inspectable.

Asset groups:
- Architecture diagrams
- Screenshots
- Sanitized journals
- GitHub commits/issues/releases
- Before/after workflow captures
- Runbooks and handoffs
- Short demo clips

### 6. Resume / Contact

Purpose: convert proof into hiring action.

Include:
- Role targets
- Selected projects
- Technical stack
- Practical strengths
- Contact links

## Homepage Copy

**Headline:** AI Operations and Automation Portfolio

**Intro:** I build practical systems that help AI-assisted work survive interruptions, tool changes, remote machines, and handoffs.

**Proof-first statement:** This portfolio is built around evidence: screenshots, sanitized journals, architecture diagrams, GitHub history, workflow examples, and outcomes.

## Visual Direction

Use a quiet technical-operations style:
- Dense but readable layout
- Off-white background with ink, steel, green, and amber accents
- Architecture diagrams and proof strips over decorative art
- Small labels, tables, timelines, and evidence cards
- Minimal animation

Avoid:
- Inflated AI language
- Abstract robot imagery
- Generic gradient hero sections
- Claims without artifacts
- Senior-developer positioning that overreaches the evidence
