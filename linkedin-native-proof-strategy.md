# LinkedIn Native Proof Strategy

## Core Adjustment

Do not make LinkedIn users leave LinkedIn first.

The public funnel should become:

**Native LinkedIn proof -> profile credibility -> Featured proof -> portfolio/GitHub links -> resume**

Links still matter, especially for recruiters and technical hiring managers who want to inspect the work. But the first impression should be native to LinkedIn: screenshots, document posts, short captions, project entries, and a clean profile.

## Why

LinkedIn is cautious with external links because they pull people away from the platform. More importantly, hiring managers are cautious with unknown links because they do not know what they are clicking.

So the strategy is:

- Show the proof directly in the feed.
- Use screenshots and PDFs as native LinkedIn assets.
- Put links in the profile, Featured section, resume, and comments only when useful.
- Make the proof understandable even if nobody clicks out.

## Best Native Formats

### 1. PDF Carousel / Document Post

Best use:
- Context Forge architecture
- Before/after workflow
- Sanitized handoff walkthrough
- "What I built" proof sequence

Why it works:
- Keeps people on LinkedIn
- Lets hiring managers skim without trust friction
- Creates dwell time
- Looks more substantial than a plain link post

### 2. Single Screenshot Post

Best use:
- One screenshot with one clear caption
- Context retrieval
- Handoff example
- Dashboard proof
- GitHub README preview

Rule:
One screenshot should prove one thing.

### 3. Text-Only Technical Story

Best use:
- Short lessons
- Build decisions
- Safety boundaries
- "What I would improve next"

Rule:
Write like a person who did the work. Avoid polished AI-post rhythm.

### 4. Featured Section

Best use:
- Permanent proof links
- Resume PDF
- Portfolio
- GitHub repo after cleanup
- PDFs of proof assets

The Featured section is where outbound links are acceptable because viewers are already on your profile and choosing to inspect more deeply.

## Link Placement Rules

### In Feed Posts

Default:
- No external link in the main post.
- End with: "I added the proof links to my Featured section."
- Or: "Comment `Context Forge` and I’ll send the link."

Use direct links in posts only when:
- Announcing the final portfolio launch
- Replying to someone who asks
- Posting after the profile already has enough native proof

### In Comments

Use sparingly.

Safer comment wording:

```text
For anyone who wants to inspect the proof chain, I put the case study and repo in my Featured section.
```

or:

```text
I can share the case study link if useful. The short version is in the carousel above.
```

### In Profile

Use links aggressively:

- Contact info
- Featured section
- Project entries
- Resume PDF
- Portfolio
- GitHub

Hiring managers expect links here.

### In Resume

Use links aggressively but cleanly:

- Portfolio
- Context Forge case study
- GitHub
- Proof library

The resume is already a click-inspection artifact.

## LinkedIn Featured Setup

Use this order:

1. **Context Forge Proof Deck**
   - Native PDF carousel uploaded to LinkedIn
   - Should explain the whole flagship case study without requiring a click

2. **Context Forge Case Study**
   - External portfolio link
   - Use after the proof deck is live

3. **Context Forge GitHub**
   - Only after the repo is immaculate

4. **Resume PDF**
   - Clickable proof links

5. **Battle Buddy Proof Deck**
   - Native PDF with sanitized screenshots and pipeline diagram

6. **Infrastructure Lab Proof Deck**
   - Native PDF with dashboards, topology, and recovery proof

```text
Context Forge | Battle Buddy | Infrastructure Lab
```

## Launch Post Without External Link

```text
I’m rebuilding my portfolio around the kind of AI work I actually want to do:

AI operations, automation, systems integration, and technical workflows that keep moving after the chat window closes.

The flagship project is Context Forge.

The problem it solves is simple: AI-assisted work loses continuity. A project can span multiple chats, models, local files, remote servers, GitHub repos, synced folders, and interruptions. Without a handoff system, the next session starts by guessing.

Context Forge creates project-scoped memory and evidence-backed handoffs so a future task, model, machine, or person can resume from what was actually verified.

I’m not positioning myself as an "AI expert." I’m positioning myself as a practical systems builder who can make AI useful in real operational environments.

I added the proof deck to my Featured section.
```

## Hiring Manager Trust Pattern

Most hiring managers will not click a random link from the feed.

They may:

1. See a screenshot or carousel.
2. Visit the profile.
3. Skim the headline and About section.
4. Check Featured.
5. Open the resume or GitHub if the proof looks credible.

Design every LinkedIn asset for that path.
